# 图书馆借阅管理系统 - 完整测试方案

## 一、测试框架设计

### 1. 分层金字塔测试架构

| 测试层级 | 测试类型 | 测试工具 | 测试重点 |
|----------|----------|----------|----------|
| **单元测试** | 组件、Service、Composable | Vitest (前端)、Jest (后端) | 功能正确性、逻辑覆盖 |
| **集成测试** | API 接口、组件集成 | Vitest + @vue/test-utils (前端)、Supertest (后端) | 模块间协作 |
| **E2E 测试** | 完整业务流程、UI 风格 | Playwright | 端到端流程、用户体验 |
| **专项测试** | 国际化、安全、性能、可访问性 | 专用工具 | 特定领域验证 |

### 2. 测试工具配置

#### 前端测试工具
- **Vitest**：单元测试和集成测试
- **Playwright**：E2E 测试
- **Storybook**：组件视觉测试
- **Lighthouse**：性能和可访问性测试

#### 后端测试工具
- **Jest**：单元测试
- **Supertest**：API 集成测试
- **Testcontainers**：数据库集成测试

## 三、测试执行计划

### 1. 测试环境配置

#### 前端测试环境
- **Vitest 配置**：`vitest.config.ts` 配置测试环境和覆盖率报告
- **Playwright 配置**：`playwright.config.ts` 配置 E2E 测试环境
- **Storybook 配置**：`main.js` 配置组件视觉测试

#### 后端测试环境
- **Jest 配置**：`jest.config.js` 配置单元测试环境
- **测试数据库**：独立的测试数据库，每次测试前清空
- **Mock 数据**：测试数据工厂和 Mock 服务

### 2. 测试脚本

#### 前端测试脚本
```json
{
  "scripts": {
    "test": "vitest run",
    "test:watch": "vitest",
    "test:coverage": "vitest run --coverage",
    "test:e2e": "playwright test",
    "test:ui": "vitest --ui",
    "storybook": "storybook dev -p 6006"
  }
}
```

#### 后端测试脚本
```json
{
  "scripts": {
    "test": "jest",
    "test:watch": "jest --watch",
    "test:cov": "jest --coverage",
    "test:e2e": "jest --testPathPattern=test/e2e"
  }
}
```

### 3. 测试执行流程

#### 本地开发测试
1. **单元测试**：`npm run test`（前端）、`npm test`（后端）
2. **集成测试**：`npm run test:e2e`（前端）、`npm run test:e2e`（后端）
3. **UI 测试**：`npm run storybook`（组件视觉测试）
4. **专项测试**：使用专用工具运行

#### CI/CD 测试
1. **PR 测试**：每次 PR 自动运行所有测试
2. **合并测试**：合并到主分支时运行完整测试套件
3. **定时测试**：每日运行完整测试套件
4. **部署测试**：部署前运行性能和安全测试

### 4. 测试数据管理

#### 测试数据工厂
- **图书数据**：生成测试用图书数据（包含不同分类、状态）
- **会员数据**：生成测试用会员数据（包含不同等级、状态）
- **借阅数据**：生成测试用借阅记录（包含正常、逾期状态）
- **预约数据**：生成测试用预约记录（包含不同状态）

#### 测试数据库
- **前端**：Mock API 响应，使用 MSW（Mock Service Worker）
- **后端**：测试专用数据库，使用 Testcontainers 管理
