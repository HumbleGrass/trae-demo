# 领域文档

说明工程技能在探索代码库时应当如何消费本仓库的领域文档。

## 探索前先阅读

- 仓库根目录的 **`CONTEXT.md`**，或
- 若存在 **`CONTEXT-MAP.md`**：它指向每个上下文各自的 `CONTEXT.md`，阅读与当前主题相关的每一份。
- **`docs/adr/`**：阅读与你即将工作的领域相关的 ADR。

若上述任一文件不存在，**静默跳过**。不必提示其缺失，也不必提前建议创建；`/domain-modeling` 技能会在术语或决策真正确定时惰性创建它们。

## 文件结构

单上下文仓库（本仓库）：

```
/
├── CONTEXT.md
├── docs/adr/
│   └── 0001-*.md
└── src/
```

## 使用词汇表用语

当输出中提及领域概念（如 issue 标题、重构提案、假设、测试名）时，使用 `CONTEXT.md` 中定义的术语，不要漂移到词汇表明确避免的同义词。若所需概念尚不在词汇表中，那是一个信号：要么你在臆造项目不用的语言（应重新考虑），要么确有缺口（记录给 `/domain-modeling`）。

## 标记 ADR 冲突

若你的输出与现有 ADR 相矛盾，应明确指出，而不是静默覆盖。
